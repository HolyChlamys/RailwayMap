# 铁路路径规划四维约束系统设计报告

## 一、系统定位与核心哲学

### 1.1 系统定位：可行铁路路径生成器

本系统**不是**路径优化器，而是**可行路径枚举器**。区别于传统路线规划追求"最快"或"最便宜"的单一最优解，本系统的核心目标是：

> **给定起点与终点，生成所有满足硬性约束的联程或直达路线，不做全局代价排序，仅做存在性枚举。**

### 1.2 设计动机

| 场景 | 说明 |
|------|------|
| **直通车票售罄** | A→B 直达买不到票，但 A→C→B 分段有票，且 AC、BC 可能在不同时间段放票，多条路径增加抢票成功率 |
| **借中转游历城市** | 放假回家不计较总耗时，借中转机会到陌生城市短暂游玩 |
| **消遣式地图浏览** | 把铁路网当地图探索，"从 A 出发我能经过哪些地方到 B" |
| **多方案备选** | 系统提供多条满足约束的路径，用户自行权衡买票难度、兴趣偏好等难以量化的因素 |

### 1.3 与"最优路径"类系统的对比

| 对比维度 | 本系统（全量探索型） | 传统最优路径系统 |
|----------|----------------------|------------------|
| **目标** | 枚举所有满足时空约束的可行路径 | 找出总耗时/总等待最短的 Top-K 路径 |
| **用户心态** | "给我选择权" | "直接告诉我哪个最好" |
| **约束特点** | 条件宽松，允许大量中转、灵活时段 | 条件收紧，总时间、接续严格限制 |
| **算法风格** | 约束过滤 + DFS 枚举 | 代价评估 + 启发式剪枝（最短路变种） |
| **输出** | 无序路径集合 | 按代价排序的路径列表 |

## 二、四维约束定义与定位

### 2.1 四维概览

四个约束维度分别指向**时间、复杂度、空间、舒适度**四个独立维度，级别相当，互不重叠。

| 要素 | 符号 | 本质维度 | 面向的规划目标 |
|------|------|----------|----------------|
| 乘车时段 | **T** | 时间窗口 | 限定时段内乘车，关注"何时在车上" |
| 中转次数 | **N** | 路径复杂度 | 控制换乘频繁度，同时赋予"分段游历"功能 |
| 中转站 | **S** | 空间约束 | 限定经停点，强地理约束 |
| 每段乘车时间 | **D** | 舒适度/段长 | 控制单段疲劳度，同时驱动多段拆分 |

### 2.2 各维度细化定义

#### 乘车时段（T）

- **含义**：对旅客可接受的列车出发、到达或途中在车上的时间区间进行约束。
- **约束形式**：`[T_start, T_end]`，以当日分钟数表示（如 360~1320 即 06:00~22:00）。
- **默认宽松**：仅排除深夜（如 0:00~6:00），保留大量日间车次。
- **作用对象**：单段乘车的发车时间和到达时间均需落在窗口内。
- **特殊用法**：可创造"在某城市过夜"路径——傍晚到站、次日晨出发。

#### 中转次数（N）

- **含义**：整个行程中旅客需要换乘列车的次数。乘车段数 = N + 1。
- **约束形式**：`[N_min, N_max]`，整数区间。
- **重点关注**：2 次及以上中转的匹配度。直达耗时 24h 时，中转 2 次可平分为 3 个 8h，中转 3 次为 4 个 6h。
- **核心价值**：N 是"多城游历可能性"的直接控制器。N 越高，路径骨架越丰富，可经过的城市越多。

#### 中转站（S）

- **含义**：对换乘发生的车站施加的地理或属性限制。
- **约束形式**：
  - **白名单模式**：仅允许在这些车站换乘。
  - **黑名单模式**：禁止在某些车站换乘。
  - **空值**：不限制，引擎自动择站。
- **注意粒度**：当前以车站为粒度，暂不处理"同城多站"场景（后续可通过预留默认时间近似处理）。
- **旅游模式**：S 可转为"兴趣白名单"，引擎尽量包含但不必全部经过。

#### 每段乘车时间（D）

- **含义**：对每一段连续乘坐同一车次的在车时长单独设置上限。
- **约束形式**：`D_max`（分钟），如 240 表示单段不超过 4 小时。
- **核心特性**：D 是**舒适度控制器**，同时是**多样性驱动器**。长距离必须被切成多段，从而催生更多中转方案。
- **与 N 的关系**：D 苛刻时 N 必须足够大。`最低 N ≈ ⌈直达总时长 / D_max⌉ − 1`。

## 三、维度间相容度矩阵

### 3.1 两两相容性分析

| 维度对 | 相容性 | 协同/冲突本质 |
|--------|--------|----------------|
| **T ↔ N** | ⚠️ 间接制约 | T 收窄可选班次，N 越高越难全部段满足 T。若禁夜行，可能需要高 N 切分段。 |
| **T ↔ S** | ✅ 基本独立 | 除非小站有特殊运营时段（半夜不办客运），一般互不影响。 |
| **T ↔ D** | ❗ 强耦合 | 段长与时段需同时满足，是规划的核心穿插约束。若 D 严且 T 仅限白天，长线路必须通过高 N 切段。 |
| **N ↔ S** | ❗ 强相关 | N 决定需要的中转站个数，S 限定可用站集合。S 过小会限制 N 的取值上限。旅游模式下若放开 S，N 可自由设置，路径多样性大增。 |
| **N ↔ D** | ✅ **正向相容** | **核心协同对。** D 苛刻时可通过增加 N 切段；N 固定时限制了 D 的严格度。两者相容度极高，是以中转换舒适分段的策略基础。 |
| **S ↔ D** | ❌ **易冲突** | S 位置固定段长。若指定站间的自然段长超出 D_max，则直接无解。例如北京→广州强制经郑州，但郑州→广州高铁仍需 6-7h，若 D_max≤4h 则矛盾。 |

### 3.2 相容度图谱

```
T ──⚠️── N        T = 乘车时段
│       │         N = 中转次数
❗      ❗        S = 中转站
│       │         D = 每段乘车时间
S ──❌── D
 │      │
 ✅     ✅
 │      │
 (T↔S 独立)  (N↔D 协同)
```

**图例**：✅协同/相容 | ⚠️可能受限 | ❗强相互制约 | ❌高冲突风险

## 四、优先维度选定后的可追加性判定

当用户选定一个维度作为"优先考虑"（硬约束），需判断其他维度能否继续追加。

### 4.1 决策总表

| 优先维度 | 追加 N | 追加 S | 追加 D | 追加 T |
|----------|--------|--------|--------|--------|
| **T（时段）** | ✅ 可追加。若 T 严苛，需提高 N 来切段。 | ✅ 可追加。需检查指定站车次是否在 T 内。 | ✅ 可追加。须逐段检查是否同时满足 T 和 D。 | — |
| **N（中转次数）** | — | ✅ 强烈推荐。可将 S 作为兴趣点而非硬性必经。需确保 S 个数与 N 兼容。 | ✅ 极好相容。高 N 天然满足严格 D。 | ✅ 可追加。每段均需符合 T，高 N 时组合空间收窄。 |
| **S（中转站）** | ✅ 可追加。N 必须 ≥ S 所需最少换乘次数。 | — | ⚠️ 风险高。S 固定段长，D 必须与之匹配，否则无解。 | ✅ 可追加。风险中等。 |
| **D（段长）** | ✅ 强烈推荐。D 可推导出最低 N，系统提示所需最少中转次数。 | ⚠️ 须严格验证。若指定 S 则段长固定，须确保均 ≤ D_max。 | — | ✅ 可追加。时段与段长协同检查。 |

### 4.2 三维确定后第四维冗余判定

当三个维度已确定时，第四个维度可能不再具备独立限制意义，可降级为偏好或不设硬约束。

| 已确定的三个维度 | 可能冗余的维度 | 原因 |
|------------------|----------------|------|
| **T, N, D** | **S** | 满足时段和段长的车次衔接会自动选出可行中转站，无需用户指定。 |
| **N, S, D** | **T** | S 与 D 已基本定义车次，发到时间自然落入某区间，T 仅用于筛选而非独立约束。 |
| **T, S, D** | **N** | 满足时段和段长的路径，换乘次数基本固定，N 只能接受建议值。 |
| **T, N, S** | **D** | 时段和中转站固定后，各段时长落在一个可计算范围，再设 D 可能多余或冲突。 |

### 4.3 旅游模式专用策略

当用户表达"不计总耗时、愿多中转游历"时：

1. **放宽 T**：设为软约束（如仅排除 0:00~6:00），或直接不设。
2. **提升 N 下限**：建议 2~4 次，作为硬约束。
3. **S 转为兴趣白名单**：列出向往城市，不必全部经过，作为权重加分而非硬性必经。
4. **D 作为核心硬约束**：保证单段舒适度（如 ≤4h），驱动路径自动分段。

在此模式下，四维相容度极高，几乎所有符合 D 的路径只要 S 不是强排他性都能成立。

### 4.4 冲突检测与降级处理

**冲突检测优先级**（从高到低提示调整）：
1. **S ↔ D 矛盾**：指定中转站导致段长超出 D_max → 建议修改 S 或放宽 D。
2. **T ↔ D 矛盾**：时段和段长无法同时满足 → 建议放宽 T 或增大 N。
3. **N 不足**：N 上限太小，无法将长段切分到 D 可接受范围 → 建议提高 N_max。

**降级策略**（四维全设导致无解时）：
- S 从"必须"降为"优先"（软约束）；
- T 从硬时段限制降为"尽量满足"；
- 保持 N 和 D 的硬性——这两个更直接关联旅途体验和游历自由。

## 五、算法设计

### 5.1 数据模型

```python
from dataclasses import dataclass, field
from typing import List, Set, Optional


@dataclass
class Train:
    """一趟车次（每日相同时刻运行，不区分具体日期）"""
    train_id: str          # 车次号，如 "G1234"
    dep_station: str       # 出发站
    arr_station: str       # 到达站
    dep_time: int          # 出发时间（当日分钟数，0-1439）
    arr_time: int          # 到达时间（当日分钟数，≥ dep_time）


class Timetable:
    """时刻表数据源"""
    def __init__(self, trains: List[Train]):
        self._dep_index = {}
        for t in trains:
            self._dep_index.setdefault(t.dep_station, []).append(t)
        for v in self._dep_index.values():
            v.sort(key=lambda x: x.dep_time)

    def get_departures(self, station: str, earliest_time: int) -> List[Train]:
        """返回指定站在 earliest_time 之后出发的所有车次"""
        all_trains = self._dep_index.get(station, [])
        return [t for t in all_trains if t.dep_time >= earliest_time]


@dataclass
class PathSegment:
    """一段连续乘车"""
    train: Train
    board_station: str
    alight_station: str
    board_time: int
    alight_time: int


@dataclass
class Path:
    """一条完整行程"""
    segments: List[PathSegment] = field(default_factory=list)

    @property
    def transfer_count(self) -> int:
        """换乘次数 = 段数 - 1"""
        return len(self.segments) - 1
```

### 5.2 约束定义

```python
@dataclass
class Constraints:
    """四维约束集合"""
    # 中转次数
    N_min: int = 0
    N_max: int = 2

    # 每段乘车时间上限（分钟）
    D_max: int = 240  # 默认4小时

    # 乘车时段（当日分钟数）
    T_start: int = 360   # 默认 06:00
    T_end: int = 1320    # 默认 22:00

    # 中转站白名单（None 表示不限制）
    allowed_transfer_stations: Optional[Set[str]] = None

    # 最小换乘时间（分钟），确保站内换乘可行
    min_transfer_time: int = 20
```

### 5.3 搜索算法：DFS 枚举

```python
def find_paths(
    start: str,
    end: str,
    timetable: Timetable,
    constraints: Constraints
) -> List[Path]:
    """
    枚举所有满足四维约束的可行路径。

    搜索策略：
    - 采用深度优先搜索（DFS），以 N_max 限制最大深度
    - 每个状态记录当前所在站、到达时间、已换乘次数、已访问站集合
    - 通过约束逐层剪枝，不做全局代价评估
    """
    results = []
    # 状态栈：(当前站, 到达时间, 已乘车段数, 路径段列表, 已访问站集合)
    # 起点到达时间设为 -min_transfer_time 以便首发车无需等待
    stack = [(start, -constraints.min_transfer_time, 0, [], {start})]

    while stack:
        cur_station, cur_time, leg_count, segments, visited = stack.pop()

        # 计算最早可出发时间（起点无需换乘等待）
        earliest_dep = cur_time + constraints.min_transfer_time if leg_count > 0 else 0
        candidates = timetable.get_departures(cur_station, earliest_dep)

        for train in candidates:
            # === 约束过滤 ===

            # 1. 乘车时段检查（发车和到达均需在窗口内）
            if not (constraints.T_start <= train.dep_time <= constraints.T_end and
                    constraints.T_start <= train.arr_time <= constraints.T_end):
                continue

            # 2. 段长检查
            duration = train.arr_time - train.dep_time
            if duration > constraints.D_max:
                continue

            new_segment = PathSegment(
                train, cur_station, train.arr_station,
                train.dep_time, train.arr_time
            )
            new_segments = segments + [new_segment]
            new_leg_count = leg_count + 1

            # === 到达终点 ===
            if train.arr_station == end:
                actual_transfers = new_leg_count - 1
                # 中转次数检查
                if not (constraints.N_min <= actual_transfers <= constraints.N_max):
                    continue
                # 中转站白名单检查（所有中间到达站）
                if constraints.allowed_transfer_stations is not None:
                    transfer_stations = {
                        seg.alight_station
                        for seg in new_segments[:-1]  # 排除终点
                    }
                    if not transfer_stations.issubset(
                        constraints.allowed_transfer_stations
                    ):
                        continue
                results.append(Path(new_segments))
                continue

            # === 非终点：继续搜索 ===

            # 已达最大换乘次数则不再扩展
            if new_leg_count - 1 >= constraints.N_max:
                continue

            # 禁止重复访问车站（防环路）
            if train.arr_station in visited:
                continue

            # 中转站白名单检查
            if (constraints.allowed_transfer_stations is not None and
                    train.arr_station not in constraints.allowed_transfer_stations):
                continue

            # 入栈继续
            new_visited = visited.copy()
            new_visited.add(train.arr_station)
            stack.append((
                train.arr_station, train.arr_time,
                new_leg_count, new_segments, new_visited
            ))

    return results
```

### 5.4 使用示例

```python
# 构造时刻表
trains = [
    Train("G101", "北京南", "济南西", 480, 600),    # 8:00-10:00
    Train("G102", "北京南", "南京南", 420, 720),    # 7:00-12:00 (直达)
    Train("G201", "济南西", "南京南", 660, 840),    # 11:00-14:00
    Train("G202", "济南西", "上海虹桥", 690, 900),  # 11:30-15:00
    Train("G301", "南京南", "上海虹桥", 900, 1020), # 15:00-17:00
    Train("G302", "徐州东", "南京南", 780, 900),    # 13:00-15:00
    Train("G401", "北京南", "徐州东", 540, 720),    # 9:00-12:00
    Train("G402", "徐州东", "上海虹桥", 780, 900),  # 13:00-15:00
]

tt = Timetable(trains)

# 设定约束：北京→上海，最多1次中转，单段≤5h，仅白天乘车
constraints = Constraints(
    N_min=0,
    N_max=1,
    D_max=300,
    T_start=360,
    T_end=1320,
    allowed_transfer_stations={"济南西", "徐州东", "南京南"},
    min_transfer_time=20
)

paths = find_paths("北京南", "上海虹桥", tt, constraints)

print(f"找到 {len(paths)} 条可行路径：")
for i, path in enumerate(paths, 1):
    print(f"\n路径 {i}（换乘 {path.transfer_count} 次）：")
    for seg in path.segments:
        dep_h, dep_m = divmod(seg.board_time, 60)
        arr_h, arr_m = divmod(seg.alight_time, 60)
        dur = seg.alight_time - seg.board_time
        print(f"  {seg.train.train_id}  {seg.board_station} → {seg.alight_station}  "
              f"{dep_h:02d}:{dep_m:02d}-{arr_h:02d}:{arr_m:02d}  "
              f"({dur}min)")
```

### 5.5 算法特性说明

| 特性 | 说明 |
|------|------|
| **完备性** | 在 N_max 限制下枚举所有满足硬约束的路径，不遗漏可行方案 |
| **剪枝策略** | 时段过滤、段长过滤、防环路、N_max 深度限制、中转站白名单过滤 |
| **时间复杂度** | 最坏 O(分支因子 ^ N_max)，受路网密度影响。实际中 D_max 和 T 会大幅削减分支 |
| **空间复杂度** | O(N_max)，DFS 栈深度受 N_max 控制 |
| **可扩展性** | 最小换乘时间固定为常量，后续可升级为站对站映射表 |
| **无全局排序** | 搜出的路径按发现顺序返回，不做总耗时/票价排序，保持"全量探索"定位 |

## 六、扩展边界与后续优化方向

### 6.1 明确搁置（不属于当前核心）

以下两个维度经充分讨论后**搁置**为未来优化，不纳入当前四维系统：

| 维度 | 搁置原因 |
|------|----------|
| **总旅行时间** | 一旦设为硬约束，相当于强制计算全局代价，会砍掉那些为了增加中转游览城市而稍有绕路的路径，与"不计总耗时"的初衷冲突 |
| **换乘时间区间** | 跨站换乘需引入外部交通数据，计算复杂度急剧上升。严格要求最小/最大换乘等待会剪掉"夜宿一城"等旅游亮点方案 |

### 6.2 未来可扩展方向

| 方向 | 说明 | 优先级 |
|------|------|--------|
| 同城多站换乘 | 同城不同站间预留默认换乘时间（如 90min），通过简单规则近似处理 | 较高 |
| 跨日运行支持 | 升级时间模型为 `(day_offset, minute)`，修改时段检查逻辑 | 较高 |
| 等时圈模块 | 独立的地图可视化工具，回答"从某站出发在 D 时间内能到哪" | 中等 |
| 软偏好排序 | 搜出所有路径后，按"途径兴趣站数量"排序，不破坏硬约束纯净性 | 中等 |
| 票价/席别筛选 | 作为次级筛选条件，在路径骨架确定后再精细化 | 较低 |

### 6.3 等时圈模块的独立定位

等时圈展示功能**不应并入四维路径规划核心**，而应作为**独立的地图可视化工具模块**：

- **功能自足**：用户可单独使用等时圈探索某城市铁路辐射范围，不涉及路径规划。
- **计算逻辑差异**：等时圈是"单源 BFS + 时间累计"的范围查询；路径规划是"带约束的 DFS 枚举"。两者可共享底层路网数据，但算法结构不同。
- **协作方式**：路径规划界面中，当用户填写"中转站 S"时，可调等时圈查看"从当前站出发在 D 时间内能到哪"，点选结果自动填入 S。
- **最终形成双入口**：
  - **等时圈工具**：从一点发散，回答"我能去哪"
  - **路径生成器**：在两点之间枚举，回答"我能怎样去"

## 七、设计总结

### 7.1 核心思想重申

```
约束过滤 ≠ 代价优化
可能性枚举 ≠ 单一答案
用户选择权 ≠ 系统推荐
```

### 7.2 四维关系速记

```
T ─ 时间窗口       N ─ 路径骨架数量
S ─ 空间锚点       D ─ 舒适与分段驱动
```

- **N ↔ D** 是核心协同对：舒适度驱动分段，分段催生多样化路径
- **S ↔ D** 是最高风险组合：指定站可能锁死段长导致矛盾
- **T ↔ D** 是日常耦合点：白天时段 + 短段长 = 必然需要更多中转

### 7.3 算法一句话

> 以 DFS 枚举路径骨架，逐层施加 T、D、S、N 四维约束过滤，在不做全局代价评估的前提下收集所有可行方案，为用户提供"不遗漏可能性"的路径集合。
