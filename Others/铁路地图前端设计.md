铁路地图项目 - 地图页前端功能需求

页面基础布局：

- 页头（Header，高度 48–56px）：左侧品牌 Logo，Logo 右侧嵌入搜索栏（含车站/车次 Tab 切换），右侧用户操作区（深色模式切换、登录/注册、关于等）。
- 底图（瓦片地图），占满页头下方全部剩余空间。
- 铁路线路图层（显示线路走向），叠加于底图之上。
- 车站标注（显示车站名称与位置），叠加于线路图层之上。
- 左侧常驻浮窗：展示车站信息或车次详情，宽度约 360px，从左侧滑入，不遮挡主要地图区域。
- 中央独立浮窗：仅展示经停车次时刻表（6 列表格），宽度约 640px，居中弹出并附带半透明遮罩层，关闭后回到左侧浮窗。
- 图例与地图控制按钮（放大、缩小、定位、图层切换）统一置于页面右上角，纵向排列。图例可折叠。
- Agent 对话面板从右侧滑入展开，宽度约占页面 1/4（360–480px），展开时可覆盖右上角图例与按钮组，关闭后恢复可见。

一、地图基础展示

- 以静态方式渲染底图、线路、车站、图例和缩放控件。
- 车站名称在地图上始终可见。

二、信息查询与交互

1. 搜索城市

   - 输入城市名称并搜索。
   - 地图自动聚焦至该城市中心，并高亮以“城市名”为开头的车站（如搜索“北京”，聚焦北京市政府，高亮“北京站”、“北京南站”、“北京丰台站”等）。
2. 搜索车次（例如 G1）

   - 在页头搜索栏输入车次号搜索。
   - 左侧常驻浮窗显示车次详细信息（车次号、类型、经停站时间轴：站名、到达时间、发车时间等）。
   - 同时在地图上以高亮动态效果绘制该车次的完整运行轨迹。
3. 搜索车站（例如 北京站）

   - 在页头搜索栏输入车站名称搜索。
   - 左侧常驻浮窗显示车站信息：名称、所属城市/属地、途经线路。
   - 浮窗内含一个按钮，文案为“所有车次”或“列车”。
   - 点击该按钮，页面中央弹出独立浮窗（带半透明遮罩层），展示该站全部经停车次（始发、终到、途经）的简略信息列表。
   - 列表项格式（6 列表格）：车次类型字母 - 车次号 - 始发站 - 终到站 - 到达时间 - 发车时间
     （若为始发站则到达时间可显示为“-”，终到站则发车时间显示为“-”）。
   - 关闭中央浮窗后回到左侧浮窗，左侧浮窗内容不丢失。
4. 地图上直接点击车站

   - 点击地图上的车站名称或图标。
   - 交互方式与“搜索车站”完全一致：左侧浮窗展示车站信息（名称、属地），内设“所有车次”按钮，点击后在页面中央弹出该站全部经停车次的简略列表。

三、通用超链接跳转

- 在以上所有浮窗/列表（车次详情、车站详情、车次列表）中，出现的“车站名称”和“车次号”以超链接样式显示（如蓝色下划线）。
- 点击任意车站名称：触发同“搜索车站/点击车站”的交互，左侧浮窗展示该站信息（含“所有车次”按钮）。
- 点击任意车次号：触发同“搜索车次”的交互，左侧浮窗展示该车次详情，并在地图上高亮动态显示运行轨迹。
- 所有跳转后的展示方式与对应搜索/点击行为保持一致，支持连续查询。

四、Agent 对话与中转路径规划

1. Agent 入口

   - 页面右下角设置圆形浮动按钮，作为 Agent 对话的常驻入口。
   - 按钮形态可为圆形图标按钮或桌面宠物式悬浮形象，始终置于地图与控制按钮之上（z-index 高于其他 UI 元素）。
   - 点击入口后，在页面右侧展开对话面板；再次点击入口或面板外部区域可关闭面板。

2. 对话面板布局

   - 面板从页面右侧滑入展开，宽度约占页面的 1/4，最小宽度 360px，最大宽度 480px。
   - 面板为浮窗或抽屉形式，顶部与页头底部齐平，高度占满页头下方全部空间，半透明背景 + backdrop-filter 模糊效果，与搜索栏、图例面板的玻璃材质风格保持一致。
   - 展开时可覆盖右上角的图例与地图控制按钮组（两者非典型同时使用场景），关闭面板后按钮组恢复可见。
   - 面板内部分为三个区域：
     - 顶部标题栏：显示标题（如“铁路助手”）、关闭按钮。
     - 中部对话列表区：占据主要高度，overflow-y 滚动，内容为聊天气泡列表。
     - 底部输入区：文本输入框 + 发送按钮，固定在面板底部。
   - 打开面板时默认展示欢迎引导内容。

3. 对话列表与气泡样式

   - 对话列表采用类聊天应用的气泡布局：
     - Agent 消息：左对齐，浅灰色或玻璃材质背景气泡，头像为机器人图标或铁路图标。
     - 用户消息：右对齐，主题色（如蓝色）背景气泡，无头像或以用户默认头像显示。
   - 每条消息气泡包含：文本内容 + 可选的时间戳（小号灰色文字）。
   - Agent 的引导消息以灰色小字或常态气泡形式优先输出当前可提供功能的提示，例如：
     - “我可以帮你查询车站信息、搜索车次、规划中转路线。直接告诉我你的需求即可。”
     - 引导语中可包含可点击的快捷提问示例（如“北京到广州怎么走”），点击后自动填入输入框。
   - 支持基本的 Markdown 渲染（加粗、列表、换行），用于 Agent 返回结构化结果。

4. 基础信息查询（Agent 对话形式）

   - 用户可通过对话向 Agent 提问车站信息、车次信息、城市车站列表等基础查询。
   - Agent 处理查询后以文字形式回复，同时触发地图上的对应可视化：
     - 查询车站 → 回复简述（如“北京站，北京市·重要枢纽站，注意左侧面板”）并在地图上选中该车站，左侧浮窗同步展示车站信息。
     - 查询车次 → 回复简述（如“G1 次，北京南 → 上海虹桥，注意左侧面板及地图高亮”）并在左侧浮窗展示车次详情、地图上绘制运行轨迹。
     - 查询城市 → 回复简述并触发城市聚焦与车站高亮。
   - Agent 文字回复以简洁的总结性话语为主，详细结构化信息仍通过左侧浮窗或中央浮窗展示，地图可视化方式与搜索框、点击交互的结果一致。

5. 中转路径规划

   - 用户向 Agent 描述出行需求，可包含以下多维约束条件：
     - 起点站、终点站（必填）。
     - 中转站（可选，可多个，可指定次序或不指定次序）。
     - 偏好类型（可选）：高铁优先（G 字头）、动车优先（D 字头）、最短时间、最少换乘。
     - 避开站点或线路（可选）。
     - 出发时间范围或到达时间范围（可选）。
   - Agent 格式化用户输入为结构化参数，调用路径规划工具或 MCP 服务，获取规划结果。
   - Agent 以文字形式回复规划结果，格式为多段车次拼接：
     ```
     方案一：A 站 —(G1)→ C 站 —(D301)→ B 站，总耗时约 6h30min，换乘 1 次
     方案二：A 站 —(G2)→ D 站 —(G89)→ B 站，总耗时约 7h15min，换乘 1 次
     ```
   - 若存在多条可选路线（宽松约束），Agent 同时列出多条方案供用户选择。

6. 路径规划 — 地图可视化

   - 当 Agent 返回一条或多条规划路线时，在地图上以高亮动态效果绘制全部路线。
   - 路线颜色规则：
     - 多条路线之间（如 A-C-B、A-D-B、A-E-B）：不同路线使用不同颜色进行区分，颜色从预定义的路线色板中依次选取。
     - 同一路线内的不同车次段落（如 A→C 段为 G1 车次，C→B 段为 D301 车次）：使用虚线动态效果与箭头实线动态效果交替，以区分段落边界。例如前一段为实线 + 流动箭头动画，后一段为虚线 + 流动动画，使段落切换处视觉上可辨识。
     - 中转站点在地图上以特殊标记（如放大脉冲或不同颜色光圈）强调显示。
   - 动态效果：所有规划路线均以流动虚线/箭头动画呈现（如 SVG stroke-dashoffset 动画），不同路线/段落的动画相位可错开，避免视觉重叠时混淆。
   - 当用户在对话中进一步增加约束条件后，地图上的路线高亮应动态更新：不再符合的路线淡出移除，保留的路线维持原有颜色不变。

7. 对话状态与地图联动

   - 对话面板与地图为联动关系，非互斥关系：面板展开时地图仍可交互（平移、缩放、点击车站）。
   - 用户可随时关闭对话面板，关闭后地图上由 Agent 绘制的高亮路线保留展示，直至用户执行新的搜索或刷新页面。
   - 对话面板支持清空对话历史或重新开始。

8. 实现范围说明

   - Agent 的 NLP 理解、对话管理、工具调用、MCP 接口等属于后端/Agent 开发范畴，前端原型阶段不做实现，仅使用 mock 数据模拟对话回复和路径规划结果。
   - 前端原型重点实现：Agent 入口按钮、对话面板布局、聊天气泡样式、消息发送/接收交互、规划结果的地图可视化（多路线多色、段落虚实区分）。
